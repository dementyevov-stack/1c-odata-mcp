# Исторические значения и сверка поступления

Статус: реализовано для исторического `write.purchase.create_purchase`
(товары + услуги). Обычные вызовы не менялись.

## 1. Три состояния поля

`src/odata/historical-fields.ts` различает:

- `omitted` — поля нет в payload; readback не объявляет его пустотой;
- `empty` — явная пустота, кодируется по типу:
  `string` → `""`, `guid` → `00000000-0000-0000-0000-000000000000`,
  `datetime` → `0001-01-01T00:00:00`, `number` → `null`;
  `boolean` пустым быть не может (`false` — значение);
- `value` — значение сохраняется как есть: `0`, `false`, пустая строка,
  ссылка, дата со временем.

Из одного описания полей строятся и payload, и требования readback. Поэтому
проверка не может опираться только на payload, уже потерявший поле.

## 2. Что изменилось в историческом поступлении

- `СуммаНДС`, единица, коэффициент, страна, идентификаторы и счета строк —
  только если заданы; исторический путь больше не подставляет счета строк
  и счета расчётов по умолчанию.
- `warehouseEmpty` отправляется явным нулевым GUID; readback ловит подмену
  склада.
- Сервисная строка с `emptyQuantity` отправляет `Количество: null`; readback
  допускает `null`/`0` как пустое числовое представление 1С, но не `1`.
- `Содержание` при отсутствии не отправляется; явная пустая строка остаётся
  явной пустой строкой.
- `Posted=false`, `DeletionMark=false`, `Date` со временем и все заданные
  поля шапки/строк обязательны для readback. Пропуск обязательного поля или
  строки — `verification: failed`.
- Обе таблицы проверяются, если в них есть строки. Несформированная таблица
  не объявляется частью контракта.
- После неудачного GET или mismatch повторный POST не выполняется; журнал
  операций и `operationId` не меняются.

## 3. Ограничения

- Проверка не доказывает тождественность бухгалтерских проводок: она сверяет
  сохранённые поля документа и строк.
- `empty`/`omitted` для необязательных полей должны задаваться вызывающей
  стороной; отсутствие поля не означает явную пустоту.
- Для новых исторических документов вне поступления модуль нужно подключать
  отдельно; глобальная семантика `clean()` не изменена.
